# Companion skills

The eight third-party skills `install-companions.sh` adds to a project are generic: each one contradicts this stack somewhere. Before following one, read its entry below. When they disagree, the project's `CLAUDE.md` and the web-dev skills win, then `node_modules/effect/AGENTS.md` and the installed types, then the companion.

- **`shadcn`**: components, composition, `Field` layout, theming. Skip its Tailwind v3 / `tailwind.config.js` branch, its RSC and `"use client"` notes (inert on Vite) and its `next-themes` setup (dark mode is not wired in the template). Its `shadcn@latest` commands, including the `info --json` it runs when loaded, are rewritten to `pnpm exec shadcn` (the lockfile-pinned CLI) by `install-companions.sh`.
- **`react-router-data-mode`**: routing and navigation, written for React Router 7. Version 8 has no `react-router-dom` and no `hasErrorBoundary`. Data loads in components through TanStack Query; a loader at most prefetches with `queryClient.ensureQueryData`. Its `useFetcher` mutations become `useMutation` with React Hook Form. Skip `references/ssr.md` and `unstable_MiddlewareContext`.
- **`react-hook-form`**: performance (`useWatch`, `useController`, field arrays). Its `zodResolver` becomes `effectTsResolver(Schema)`; skip its `integ-shadcn-*` rules (the old `Form` / `FormField`). Its raw `fetch` with `setError('root.serverError')` becomes `setFormErrors(form.setError, error, form.getValues())`, which writes `root.server`; its `useQuery({ queryFn: fetchX })` becomes a `queryOptions` factory with `runEffect`.
- **`react-testing`**: React Testing Library patterns. Vitest only (`vitest-axe` for axe); MSW imports come from `msw/http`, not the `msw` root (MSW 2 style); the first load is `isPending`. It defines its own `renderWithProviders`: import the project's from `@/test/render`. Its cross-references point at files that do not exist.
- **`vitest`**: matchers, fake timers, `vi.fn`, config. The network is mocked with MSW only, never `vi.stubGlobal('fetch')` or `vi.mock` of an API module; commands use pnpm; `expect.schemaMatching` takes an Effect Schema through `Schema.toStandardSchemaV1`; Browser Mode is not used.
- **`vite`**: config and plugins. Skip its SSR and library-mode parts and the classic `jsxInject` snippet.
- **`vercel-react-best-practices`**: client-side performance (`rerender-*`, `js-*`, `advanced-*`, most `bundle-*`). Skip `server-*`, `async-api-routes`, `async-suspense-boundaries`, `rendering-hydration-*`, `rendering-resource-hints` and `rendering-script-defer-async`. `next/dynamic` becomes `React.lazy`, `optimizePackageImports` direct imports, SWR TanStack Query, and the raw `fetch` / Promise examples (`async-parallel`, `async-defer-await`) `Effect.all` with `concurrency`.
- **`vercel-composition-patterns`**: compound components and React 19 APIs. Its React Native `TextInput` examples become DOM and shadcn components.

Two parts of the stack have no companion on purpose. Effect's official guide ships with the package: `node_modules/effect/AGENTS.md`. The available TanStack Query skill contradicted this stack in most examples (raw `fetch` query functions, `error.message` instead of tagged errors, `isLoading`, Suspense-first, TanStack Router loaders, SSR); `api-integration`'s `references/react-query.md` is the source instead.
